# AGENTS.md

Laravel 10 (PHP `^8.1`) + Blade. HR/attendance app (BUMDESMA) layered on a public promo site. `README.md` is stock Laravel boilerplate — ignore it.

## Commands

```bash
php artisan serve                    # dev server (http://localhost:8000)
php artisan migrate --seed           # full setup; seeds accounts (see below)
php artisan migrate:fresh --seed     # clean reset
php artisan test                     # or: vendor/bin/phpunit
php artisan test --filter=ExampleTest # single test/class
./vendor/bin/pint --test             # lint check (laravel/pint, no config file = defaults)
./vendor/bin/pint                    # autofix
```

No `composer test` / npm test scripts, no CI, no `opencode.json` — use the commands above verbatim. `npm run dev|build` is dead weight (no Blade view uses `@vite`; all pages load Bootstrap/CDN + inline `<style>`/`<script>` — Node is NOT needed on the server). `Dockerfile` (Railway) skips `npm run build` and runs `migrate --force --seed` + `storage:link` on every start — seeders are idempotent (`updateOrCreate`/`firstOrCreate`), don't "optimize" that away.

## Architecture (not obvious from filenames)

- `routes/web.php` is the whole app; `routes/api.php` is an unused Sanctum stub (`GET /user` only). Don't add API routes unless asked.
- Two domains in one file: public promo pages (`/`, `/{page}` via `HomeController@index|page`) + authenticated HR (`/dashboard`, `/attendance`, `/leave-requests`, `/payroll`, `/recognition`, `/reports/*`, `/employees*`). All HR routes sit inside `middleware('auth')`.
- Catch-all `Route::get('/{page}')` with `whereIn` (`tentang`, `profil-lkd`, `profil`, `kegiatan`, `program`, `potensi`, `berita`, `galeri`, `kontak`) **must stay last** — anything after it is unreachable. `tentang` and `profil-lkd` are aliases for the `profil` content slug (`HomeController@page`).
- Role gate: `admin` alias (`app/Http/Kernel.php` → `AdminMiddleware`) aborts 403 unless `User::isAdmin()` (`role === 'admin'`). Admin-only: employee CRUD, payroll generate/status, recognition writes, attendance settings + locations + early-checkout approval, manual attendance corrections (`attendance.corrections.*`: input/koreksi, recomputes late/work minutes via `CheckoutPolicy::workTimes`, resets checkout approval, never touches photo/GPS evidence), `/holidays*` CRUD (dates auto-excluded from workday counts in reports only — `ReportController::workdays` skips holidays, `PayrollController::workdays` counts weekdays and ignores them), and `PATCH /leave-requests/{leaveRequest}/review`. Reports (`/reports/*`) are NOT admin-only — see below.
- Checkout rule (`App\Services\CheckoutPolicy::checkoutEligibility`, server time only): in-window checkout needs no approval; early checkout (before window) needs admin approval (`approved` + type `early|special` bypasses the window, including `too_late`); post-window checkout without approval is rejected (`too_late`). Window math lives in `CheckoutPolicy::workTimes` — employee `WorkSchedule` overrides `AttendanceSetting`. Note: `workTimes` also resolves `tolerance`, but nothing consumes it — `AttendanceController::checkIn` marks `late` for any minute past start, so don't invent grace-period logic unless asked.
- Admins are blocked from check-in/out (`AttendanceController` aborts 403 for admins) — test attendance flows as an employee user.
- Attendance evidence: check-in/out require selfie + GPS (`photo|latitude|longitude|accuracy`, photo ≤2 MB → `attendance/check-in|check-out/Y/m` on `public` disk). Radius is enforced server-side by `AttendanceLocationService::check` (Haversine) against the active `AttendanceLocation`; no active location = record-only (`*_location_valid = null`). Check-in enforces radius only when `enforce_radius` is on (seed default on); check-out is record-only unless `enforce_checkout_radius` is on (migration default off). Office (`AttendanceLocationSeeder`): `Kantor BUMDESMA TARUB LKD`, Tarub Tegal (-6.926433, 109.185844), radius 100 m, max GPS accuracy 500 m (loose on purpose for laptop WiFi GPS). `attendance.show` (owner or admin only) has the Leaflet map.
- Employee routes are duplicated: `/employees*` and `/admin/karyawan*` both map to `EmployeeController`. Prefer `/employees*` for new links.
- Reports (`ReportController` + `App\Exports\ReportExport`): open to all roles — karyawan are force-scoped to their own `employee_id` (all queries + exports), admins see everyone. `index` is the real handler, filtered by `?type=` (`all|attendance|leaves|payroll|reward-punishment|employees|visits`) + `month/year/employee_id/status`; the sibling routes (`attendance|leaves|payroll|reward-punishment|employees` — no `visits` wrapper, use `?type=visits`) are thin wrappers that merge `type` then call `index`. `type=all` renders every section; excel (`App\Exports\ReportSheet` multi-sheet via `ReportExport`) exports one styled sheet per section (pita judul + periode, header warna per seksi, zebra, freeze, filter, format Rp/`0.0%`, kolom `No`, label Indonesia, sorotan status kondisional, lampu lalu lintas % kehadiran, baris TOTAL payroll, tab warna, setup cetak landscape A4) — `type=all` = 6 sheet. `/print` renders `reports.print`; `/pdf` downloads it via `barryvdh/laravel-dompdf` (A4 landscape); `/excel` via `maatwebsite/excel`. Print/PDF pakai judul seksi berwarna per seksi (sama dengan Excel), label Indonesia, pill status, lampu % kehadiran, dan baris TOTAL payroll — CSS harus dompdf-aman (tabel untuk layout, tanpa flex/grid). Punishment `Nilai` shows `N poin` for `points_deduction` rows with points, else Rp amount.
- Auto late points (`RecognitionController@generateAutoPoints`, admin, `POST /recognition/auto-points`): aggregates an employee's monthly `late` minutes into one `punishments` row (`type=points_deduction`, `amount=0`, `is_auto=true`) using `attendance_settings` (`auto_late_points_enabled`, `late_points_block_minutes` default 15, `late_points_per_block` default 1; ceil rounding, partial block counts full). Idempotent per month (deletes prior auto rows, manual rows untouched); payroll money math unchanged. Rule is edited in `attendance.settings`.
- Dead schema, no code behind it — don't build on it unless asked: `reward_rules`, `punishment_rules` tables (+ `*_rule_id` fillables) and `qr_attendances`.
- Key models (`app/Models/`): `User -(hasOne)-> Employee`; `Employee` belongs to `User|Position|WorkSchedule`, uses `SoftDeletes` (reports + employee index query `withTrashed()`). Others: `Attendance, LeaveRequest, LeaveQuota` (annual quota, default 12 days via `LeaveQuota::current()/usage()`, enforced on approval in `LeaveRequestController`), `Payroll, Reward, Punishment, Holiday, SalaryComponent, Content`. Leave rule (`LeaveRequestController@store`): type `leave` must be filed ≥7 calendar days ahead (sick exempt); rejection requires `rejection_reason` ≥10 chars; review is locked once processed (`pending` only). Visits (`VisitAttendanceController`, `VisitAttendance::MAX_PER_DAY = 10`): max 10/day per employee enforced in `store`, photo + GPS required like attendance; karyawan see only their own, admins see all but coordinates/map points only when `?employee_id=` is set. Visual reference: `docs/erd-sistem-absensi.drawio` (+ `.png`) confirms relations and marks dead tables as struck-through; `docs/erd-chen.png` is the Chen-notation render (rectangles/diamonds/ovals); `docs/usecase-*.png` show admin vs karyawan flows; `docs/activity-diagram-kunjungan.drawio` (+ `.png` render) is the visit-recording flow (max 10/day).
- Seeders (`database/seeders/DatabaseSeeder.php` runs all four, all idempotent): `ContentSeeder` + `AttendanceSeeder` (creates `Staff` position + `Jam Kerja Reguler` schedule Mon–Fri 08:00–15:00; `admin@bumdesma.test` / `password` is skipped when `APP_ENV=production`) + `AttendanceLocationSeeder` + `KaryawanBaruSeeder` (permanent staff `KRY-007`–`KRY-013`, runs in ALL envs incl. production, password `12345678`). `KRY-001`–`KRY-006` were deleted and their seeders removed — do not reintroduce demo employees. Staff logins: `zila|sus|andry|oka|ludi|zaeni|tamami@bumdesma.test`. The checked-in `.env` sets `APP_ENV=production`, so don't expect the admin login after seeding until you set `APP_ENV=local`. Prod admin is created via `php artisan admin:create` (interactive; `--name/--email/--password` options). Demo employees (`KRY-001`–`KRY-006`) are purged via `php artisan demo:purge` (`--force` skips confirm; deactivates + soft-deletes like the UI, history kept). Daily MySQL backups: `php artisan db:backup --keep=7` (scheduled 01:00; enable cron `schedule:run` on the server — on Railway this needs a separate Cron service running `php artisan schedule:run` every minute, the web container does NOT run the scheduler; requires `mysqldump` on PATH, mysql-only — command aborts on non-mysql; backups land in `storage/app/backups`, so they only survive redeploys inside the `/data` volume).

## Env / test gotchas

- Local DB is MySQL: `DB_DATABASE=bumdesma_tarub` in `.env`. No SQLite fallback.
- `phpunit.xml` sets `APP_ENV=testing` + array drivers but **has `DB_CONNECTION=sqlite` / `DB_DATABASE=:memory:` commented out** — tests hit the real MySQL DB unless you override env. Critical: `RefreshDatabase` is used by `AttendanceEvidenceTest`, `AttendanceManagementTest`, `AutoLatePointsTest`, and `LeaveRequestRuleTest` — any of them will wipe whatever DB they point at. Never run the suite against the dev DB; point env at an empty scratch MySQL DB first, e.g. `DB_DATABASE=bumdesma_test DB_PASSWORD=... php artisan test --filter=AttendanceEvidenceTest`. Only `ExampleTest` (hits `/` expecting 200) and `LogoutTest` (no DB writes) are safe without that.
- Public promo content comes from the `contents` table (`ContentSeeder`, type `page` + `slide|program|activity|product|news|gallery`) rendered via `content.blade.php` (`page` action aborts 404 on unknown slug) and `welcome.blade.php`. `HomeController` falls back to hardcoded defaults on `QueryException`, so missing tables don't crash public pages.
- Uploads: employee photos on the `public` disk (`employee-photos`, served via `asset('storage/...')` — run `php artisan storage:link` after fresh setup or images break; if images still 404, check `public/storage` is a symlink/junction to *this* project's `storage/app/public`, not a stale real folder or a link to another project — delete it and re-run `storage:link`). Leave attachments use the default `local` disk (`leave-attachments`, served only via the auth-gated `leave.attachment` download route — not publicly accessible). Profile photo changes have a 1-week cooldown (`ProfileController::photoCooldown` via `photo_updated_at`); don't remove it as a bug.
- Railway deploy: set `APP_URL` to the public `https://...` domain (email reset links, `detail_url` JSON depend on it). `TrustProxies::$proxies` is `'*'` behind Railway's proxy. The attendance modal `fetch` uses relative URLs (`route(..., [], false)`) so it stays same-origin even if `APP_URL` is wrong; keep it that way. Photo persistence: container FS is wiped on redeploy — attach a Volume mounted at `/data` + set `STORAGE_PATH=/data` (`bootstrap/app.php` redirects storage there and auto-creates subdirs; `storage:link` on boot follows automatically). See `.env.example` for the full production checklist (`APP_KEY`, `APP_DEBUG=false`, `SESSION_SECURE_COOKIE=true`, `MAIL_*`).
- Vercel deploy (serverless, runtime `vercel-php@0.6.2`): entry `api/index.php` → `public/index.php`; `vercel.json` routes `/build|images|favicon|robots` to static files, everything else to the function; safe env defaults baked in (`SESSION_DRIVER=cookie`, `LOG_CHANNEL=stderr`, `VIEW_COMPILED_PATH=/tmp/views`). `bootstrap/app.php` redirects storage to `/tmp/laravel-storage` when `VERCEL` is set (only `/tmp` is writable). Still required in the Vercel dashboard: `APP_KEY`, `APP_URL`, `DB_*` (external MySQL — Vercel has none), `MAIL_*`; run `migrate --force --seed` + `admin:create` once from local against the prod DB. Limits: uploads are ephemeral in `/tmp`, scheduler/backup don't run.
