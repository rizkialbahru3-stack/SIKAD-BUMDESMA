# AGENTS.md

Laravel 10 (PHP `^8.1`) + Blade. HR/attendance app (BUMDESMA) layered on a public promo site. `README.md` is stock Laravel boilerplate — ignore it.

## Commands

```bash
php artisan serve                    # dev server (http://localhost:8000)
php artisan migrate --seed           # full setup; seeds demo accounts (see below)
php artisan migrate:fresh --seed     # clean reset
php artisan test                     # or: vendor/bin/phpunit
php artisan test --filter=ExampleTest # single test/class
./vendor/bin/pint --test             # lint check (laravel/pint, no config file = defaults)
./vendor/bin/pint                    # autofix
```

No `composer test` / npm test scripts, no CI, no `opencode.json` — use the commands above verbatim. `npm run dev|build` is dead weight (see Frontend note); Node is NOT needed on the server. `Dockerfile` (Railway) skips `npm run build` and runs `migrate --force --seed` + `storage:link` on every start — seeders are idempotent (`updateOrCreate`/`firstOrCreate`), don't "optimize" that away.

## Architecture (not obvious from filenames)

- `routes/web.php` is the whole app; `routes/api.php` is an unused Sanctum stub (`GET /user` only). Don't add API routes unless asked.
- Two domains in one file: public promo pages (`/`, `/{page}` via `HomeController@index|page`) + authenticated HR (`/dashboard`, `/attendance`, `/leave-requests`, `/payroll`, `/recognition`, `/reports/*`, `/employees*`). All HR routes sit inside `middleware('auth')`.
- Catch-all `Route::get('/{page}')` with `whereIn` (`tentang`, `profil-lkd`, `profil`, `kegiatan`, `program`, `potensi`, `berita`, `galeri`, `kontak`) **must stay last** — anything after it is unreachable. `tentang` and `profil-lkd` are aliases for the `profil` content slug (`HomeController@page`).
- Role gate: `admin` alias (`app/Http/Kernel.php:57`) → `AdminMiddleware` aborts 403 unless `User::isAdmin()` (`role === 'admin'`). Admin-only: employee CRUD, payroll generate/status, recognition writes, attendance settings + locations + early-checkout approval, manual attendance corrections (`attendance.corrections.*`: input/koreksi, recomputes late/work minutes via `CheckoutPolicy::workTimes`, resets checkout approval, never touches photo/GPS evidence), `/holidays*` CRUD (dates auto-excluded from workday counts in reports + payroll), all `/reports/*`, and `PATCH /leave-requests/{leaveRequest}/review`.
- Checkout rule (`App\Services\CheckoutPolicy::checkoutEligibility`, server time only): in-window checkout needs no approval; early checkout (before window) needs admin approval (`approved` + type `early|special` bypasses the window, including `too_late`); post-window checkout without approval is rejected (`too_late`). Window math lives in `CheckoutPolicy::workTimes` — employee `WorkSchedule` overrides `AttendanceSetting`. Note: `workTimes` also resolves `tolerance`, but nothing consumes it — `AttendanceController::checkIn` marks `late` for any minute past start, so don't invent grace-period logic unless asked.
- Admins are blocked from check-in/out (`AttendanceController` aborts 403 for admins) — test attendance flows as an employee user.
- Attendance evidence: check-in/out require selfie + GPS (`photo|latitude|longitude|accuracy`, photo ≤2 MB → `attendance/check-in|check-out/Y/m` on `public` disk). Radius is enforced server-side by `AttendanceLocationService::check` (Haversine) against the active `AttendanceLocation`; no active location = record-only (`*_location_valid = null`). Check-in enforces radius only when `enforce_radius` is on (seed default on); check-out is record-only (boleh dari lapangan) unless `enforce_checkout_radius` is on (migration default off). Office (`AttendanceLocationSeeder`): `Kantor BUMDESMA TARUB LKD`, Tarub Tegal (-6.926433, 109.185844), radius 100 m, max GPS accuracy 500 m (loose on purpose for laptop WiFi GPS). `attendance.show` (owner or admin only) has the Leaflet map.
- Employee routes are duplicated: `/employees*` and `/admin/karyawan*` both map to `EmployeeController`. Prefer `/employees*` for new links.
- Reports (`ReportController` + `App\Exports\ReportExport`): `index` is the real handler, filtered by `?type=` (`all|attendance|leaves|payroll|reward-punishment|employees`) + `month/year/employee_id/status`; the sibling routes are thin wrappers that merge `type` then call `index`. `/print` renders `reports.print`; `/pdf` downloads it via `barryvdh/laravel-dompdf` (A4 landscape); `/excel` via `maatwebsite/excel`. Punishment `Nilai` shows `N poin` for `points_deduction` rows with points, else Rp amount.
- Auto late points (`RecognitionController@generateAutoPoints`, admin, `POST /recognition/auto-points`): aggregates an employee's monthly `late` minutes into one `punishments` row (`type=points_deduction`, `amount=0`, `is_auto=true`) using `attendance_settings` (`auto_late_points_enabled`, `late_points_block_minutes` default 15, `late_points_per_block` default 1; ceil rounding, partial block counts full). Idempotent per month (deletes prior auto rows, manual rows untouched); payroll money math unchanged. Rule is edited in `attendance.settings`.
- Dead schema, no code behind it — don't build on it unless asked: `reward_rules`, `punishment_rules` tables (+ `*_rule_id` fillables) and `qr_attendances`.
- Key models (`app/Models/`): `User -(hasOne)-> Employee`; `Employee` belongs to `User|Position|WorkSchedule`, uses `SoftDeletes` (reports + employee index query `withTrashed()`). Others: `Attendance, LeaveRequest, Payroll, Reward, Punishment, Holiday, SalaryComponent, Content`.
- Seeders: `DatabaseSeeder` runs `ContentSeeder` + `AttendanceSeeder` (also creates `Staff` position + `Jam Kerja Reguler` schedule, then `admin@bumdesma.test` + `KRY-001`) + `DemoKaryawanSeeder` (`KRY-002`–`KRY-006`) + `AttendanceLocationSeeder` + `KaryawanBaruSeeder` (permanent staff `KRY-007`–`KRY-013`, runs in ALL envs incl. production). Demo logins (password `password`): `admin@bumdesma.test` (admin), `kry-001@bumdesma.test` – `kry-006@bumdesma.test`. Staff logins (password `12345678`, change after first login): `zila|sus|andry|oka|ludi|zaeni|tamami@bumdesma.test`. Demo users are skipped when `APP_ENV=production` — create the prod admin via `php artisan admin:create`. Daily MySQL backups: `php artisan db:backup --keep=7` (scheduled 01:00; enable cron `schedule:run` on the server; requires `mysqldump` on PATH, mysql-only — command aborts on non-mysql).

## Env / test gotchas

- Local DB is MySQL: `DB_DATABASE=bumdesma_tarub` in `.env`. No SQLite fallback.
- `phpunit.xml` sets `APP_ENV=testing` + array drivers but **has `DB_CONNECTION=sqlite` / `DB_DATABASE=:memory:` commented out** — tests hit the real MySQL DB unless you override env. Critical: `AttendanceEvidenceTest` uses `RefreshDatabase` and will wipe whatever DB it points at — never run it against the dev DB; point env at an empty scratch MySQL DB first, e.g. `DB_DATABASE=bumdesma_test DB_PASSWORD=... php artisan test --filter=AttendanceEvidenceTest`. `ExampleTest` (no `RefreshDatabase`, hits `/` expecting 200) and `LogoutTest` (no DB writes) are safe.
- Frontend: no Blade view uses `@vite` — all pages load Bootstrap/CDN assets + inline `<style>`/`<script>`. `resources/css|js/app.js` and `public/build` are dead weight (the `data-public-header` scroll effect + carousel JS in `app.js` never run — cosmetic only, don't "fix" by wiring Vite unless asked).
- Public promo content comes from the `contents` table (`ContentSeeder`, type `page` + `slide|program|activity|product|news|gallery`) rendered via `content.blade.php` (`page` action aborts 404 on unknown slug) and `welcome.blade.php`. `HomeController` falls back to hardcoded defaults on `QueryException`, so missing tables don't crash public pages.
- Uploads: employee photos on the `public` disk (`employee-photos`, served via `asset('storage/...')` — run `php artisan storage:link` after fresh setup or images break; if images still 404, check `public/storage` is a symlink/junction to *this* project's `storage/app/public`, not a stale real folder or a link to another project — delete it and re-run `storage:link`). Leave attachments use the default `local` disk (`leave-attachments`, served only via the auth-gated `leave.attachment` download route — not publicly accessible). Profile photo changes have a 1-week cooldown (`ProfileController::photoCooldown` via `photo_updated_at`); don't remove it as a bug.
- Railway deploy: set `APP_URL` to the public `https://...` domain (generated absolute URLs — email reset links, `detail_url` JSON — depend on it). `TrustProxies::$proxies` is `'*'` because the app runs behind Railway's proxy. The attendance modal `fetch` uses relative URLs (`route(..., [], false)`) so it stays same-origin even if `APP_URL` is wrong; keep it that way.
- Vercel deploy (serverless, runtime `vercel-php@0.6.2` = PHP 8.2): entry `api/index.php` → `public/index.php`; `vercel.json` routes `/build|images|favicon|robots` to static files, everything else to the function; safe env defaults baked in (`SESSION_DRIVER=cookie`, `LOG_CHANNEL=stderr`, `VIEW_COMPILED_PATH=/tmp/views`). `bootstrap/app.php` redirects storage to `/tmp/laravel-storage` when `VERCEL` env is set (only `/tmp` is writable). Still required in the Vercel dashboard: `APP_KEY`, `APP_URL`, `DB_*` (external MySQL — Vercel has none), `MAIL_*`; run `migrate --force --seed` + `admin:create` once from local against the prod DB. Known limits: uploads live in ephemeral `/tmp` (foto absen bisa hilang antar-instance — butuh S3 untuk permanen), scheduler/backup tidak jalan, PDF/Excel export bisa cacat (runtime tanpa gd/zip).
